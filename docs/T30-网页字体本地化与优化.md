# T30 · 网页字体本地化 + App 优化

> 对应任务清单第 5 项：「全面优化 App，并在 App 上使用网页端字体显示，可以直接将字体打包进安装包」。
> 版本：`0.0.14+14`（versionCode 2014）。

---

## 一、问题有多大（真机同构实测）

用与 App WebView 相同的 UA / 视口在真实站点上量了一次「一次首页加载的字体流量」：

| 文件 | 大小 |
|---|---|
| `tianheng/TH-Tshyn-P1.woff2` | **7.88 MB** |
| `tianheng/TH-Tshyn-P0.woff2` | **5.82 MB** |
| `klee-one/KleeOne-Regular.woff2` | **2.86 MB** |
| Sarasa UI SC 子集（Regular/SemiBold/Bold/Light + extra） | 1.87 MB |
| FontAwesome（solid/regular/brands） | 0.30 MB |
| Boxed、其余 | 0.03 MB |
| **合计** | **≈ 19.2 MB** |

交接文档里「站点已子集化 ⇒ App 流量已大降」的结论**不成立**：
子集化只覆盖了 Sarasa，而字体栈是
`'Sarasa UI SC','PingFang SC','Microsoft YaHei','TH-Tshyn',sans-serif` ——
Android 上既没有 PingFang 也没有雅黑，**`TH-Tshyn` 就是实际兜底面**；
只要页面上出现一个 Sarasa 子集没覆盖的字符，浏览器就去下载那个 5–8 MB 的分片。

## 二、方案：把字体打进 APK，用 `data:` URI 顶掉站点规则

`lib/src/data/embedded_fonts.dart` 三步走（顺序不能换）：

1. **闸门（hold）**：页面一开始加载就注入
   `*:not(#a):not(#b):not(#c){font-family:<占位族>!important}`。
   `@font-face` 只在「有元素用到该族」时下载，没有需求就没有请求。
   > ⚠️ 选择器必须是 `*:not(#id)…` 这种**带 id 的形状**：站点自定义 CSS 里有若干
   > `font-family:…!important`（`.header-info p{Klee One}`、`.center-text{Boxed}`），
   > 同层 `!important` 比特指度，`body *`(0,0,2) 输给 `.header-info p`(0,1,1)。
   > 实测漏的正是这两条。
2. **删掉站点的 `@font-face` 规则**：样式表与页面同源，`sheet.cssRules` 可读可写。
   凡 `src` 落在 `/ybh-fonts/` 下的规则**整条删除**：打包过的稍后补回，
   没打包的（TH-Tshyn、Sarasa J/K/HC/TC 全量族）就此消失，渲染回退系统字体。
   > ⚠️ 必须先把 `url()` 解析成绝对地址 —— FontAwesome 的 `all.min.css` 写的是
   > `url(../webfonts/fa-solid-900.woff2)`，字符串里根本没有 `ybh-fonts`。
3. **插入内联规则并放开闸门**：一条 `<style>`，`src` 用 `data:font/woff2;base64,…`，
   `font-family / weight / style / unicode-range` 与站点规则逐条对应
   （描述符在构建期从站点 CSS 解析进 `assets/fonts/manifest.json`），然后移除闸门。

### 打包清单（`assets/fonts/`，16 个文件 / 4.47 MB）

```
slice/SarasaUiSC-{Light,Regular,SemiBold,Bold}.{subset,extra}.woff2   8 个  2.47 MB
slice/LXGWWenKai-Regular.{subset,extra}.woff2                         2 个  1.01 MB
klee-one/KleeOne-Regular.woff2  ← fontTools 子集化到全站语料（3448 字） 1 个  0.88 MB（原 2.86 MB）
fontawesome/webfonts/fa-{solid-900,regular-400,brands-400}.woff2      3 个  0.30 MB
Boxed-Regular.woff2                                                    1 个  0.03 MB
empty.woff2 / manifest.json                                            2 个
```

**未打包**（体积换收益不划算，规则会被删掉，回退系统字体）：
`TH-Tshyn` 四个分片共 **29 MB**、`Sarasa UI J/K/HC/TC` 全量族共 **300+ MB**（换肤用，从不下发）。

## 三、走过弯路（避免后人重踩）

| 方案 | 结论 |
|---|---|
| **往 `<head>` 追加同名 `@font-face` 覆盖** | ❌ 无效。Chrome 对同族同字重同字形取**最先声明**那条，追加在后面不生效（真实页面 A/B 验证过） |
| **改写 CSSOM 里已有规则的 `src`** | ❌ 无效。Chrome 不会为被改写的 `CSSFontFaceRule` 重建 FontFace：原字体不再下载（看着像成功），新字体也永不加载，整页静默退回系统字体。必须**删旧规则 + 插新规则** |
| **本机 HTTP 服务 `http://127.0.0.1:port`** | ❌ 无效。https 公网页访问回环地址受 **Local Network Access** 管辖，浏览器直接拒绝：`Permission was denied for this request to access the 'loopback' address space` —— **请求根本不会发出**（服务端一个包都收不到），加任何 CORS / `Access-Control-Allow-Private-Network` 头都无用 |
| **等到 `DOMContentLoaded` 再放开闸门** | ⚠️ 太晚。本站同步脚本多，实测 DOMContentLoaded 要 3 秒后才到，用户会盯着系统字体看 3 秒。改为「样式表数量连续 8 拍不变」即放开（≈0.7–0.9 秒） |
| **站点侧字体 `<link rel=preload as=font>`** | 预加载扫描器发起，页面 JS 无法取消 ⇒ 已在主题 v1.3.2 去掉（见下） |

## 四、站点侧配合（主题仓库）

1. **去掉字体预加载**（`inc/ybh/bootstrap.php::ybh_resource_hints()`）：
   `<link rel=preload as=font>` 由预加载扫描器发起、页面 JS 无法取消，
   是客户端字体本地化**唯一无法在客户端修补的漏点**；
   子集化后两个字重合计 0.88 MB，收益已不抵无条件下载的代价。
2. **构建期语料**：`assets/fonts/manifest.json` 的描述符由站点 `css/ybh.css`
   与 FontAwesome `all.min.css` 解析而来；站点换字体后需要重跑一次生成脚本。
